# Frontend

> **State:** local development and validation instructions.

- Read `package.json` for commands and dependencies; `src/App.tsx` for routes.
- Use the Node version in `.node-version`. Reproducible install: `npm ci`.
- Development: `npm run dev`. Verification: `npm test` and `npm run build`, in this directory.
- Strict TypeScript, no `any`; preserve existing types and the PT-BR/EN/neutral Latin American Spanish content.
- `src/contracts/` contains generated bindings. Fix the source and regenerate through the authorized deploy flow; do not edit the result by hand.
- `src/levels/manifest.test.ts` verifies consistency between catalog, contracts and content.
- `src/styles/base.css` is the sheet that ships (imported by `src/main.tsx`). `src/styles/passkey-mobile.css` is imported after `base.css`. The design tokens at the top of `base.css` are `--season-*` for game surfaces, `--os-*` for Breaker OS and `--text-*` for the type scale; use them instead of new literals.
- `LevelHero.tsx` renders the slides and controls loading, navigation and carousel gestures.
- `BreakerDevice.tsx` keeps the device shell, state and apps.
- `src/levels/story/` and `src/levels/book/` are active game content; do not confuse them with reference folders in the root.
- A mocked login is not authentication. `localStorage` does not prove case completion.
- For UI changes, check loading, error and no-wallet states, keyboard, mobile and reduced motion. Only claim a visual check if you opened the app.

## PWA and assets

- Fonts are self-hosted in `public/fonts` and declared with `@font-face` at the top of `base.css`. `index.html` preloads the two latin files; it must not reference `fonts.googleapis.com` or `fonts.gstatic.com`.
- Responsive variants are generated by `npm run images` (`scripts/generate-images.mjs`, `sharp`) into `public/images/**` and recorded in `src/levels/image-variants.json`. Commit the outputs. Run it after adding or replacing level, homepage, season, login or brand logo art; `manifest.test.ts` and `images.test.ts` fail on missing variants. The header and login logo are served through `ResponsiveImage` (AVIF with WebP fallback).
- `ResponsiveImage` renders `<picture>` with AVIF and WebP. The `<picture>` uses `display: contents` so existing grid, absolute and flex selectors keep applying to the `<img>`.
- `vite-plugin-pwa` generates `dist/sw.js` and injects registration. `public/sw.js` must not exist and `main.tsx` must not register a worker. Navigations are `NetworkFirst` with navigation preload; images are `StaleWhileRevalidate`, so bump the cache names when art changes.
- The hero preload script in `index.html` duplicates the level-cover naming (`optimizedCovers`); change both together.
- `vercel.json` lives in `frontend/` and assumes the Vercel Root Directory is `frontend`. It sets the security headers and a report-only CSP. The CSP hash covers the inline preload script in `index.html`; recompute it whenever that script changes, and promote the policy to enforcing only after testing it with the wallets.
- Installed app: Android requests `fullscreen` through `display_override` (falling back to `standalone`); iOS uses `black-translucent` + `viewport-fit=cover`, so content draws under the status bar. The header, hero, login and dialog apply `env(safe-area-inset-top)`; do not remove those paddings.

## Mobile gameplay

- The mobile mode is chosen by `(max-width: 1100px) and (any-pointer: coarse)` in `src/platform/viewport.ts`; `src/styles/base.css` and `src/styles/passkey-mobile.css` mirror the query. Change all three together. `any-pointer` is deliberate: an iPad with a trackpad still has a coarse touch pointer.
- On mobile the wallet can be a passkey. It needs HTTPS (localhost is accepted for development; `127.0.0.1` is rejected), Testnet, and a platform authenticator. The account wasm hash and WebAuthn verifier are deployment facts in `PASSKEY_DEPLOYMENT` (`src/wallet/passkey-engine.ts`), not in `deployments.json`; update them when the account or verifier is redeployed.
- The **Operations** app is available inside Breaker OS on mobile and desktop. On desktop, the browser DevTools console remains the primary terminal. Keep the `*.mobile` copy in `src/i18n/texts.ts` aligned with all three paths in PT-BR, EN and ES.
- Operations is the **Breach Room**: `BreachRoom.tsx` opens directly on the existing notebook cells, without tab navigation. Revealed evidence lives in the dossier and opens its linked document. The Level passes `CaseSubmit` state/callbacks for validation and diagnostics; on desktop, the browser console remains the primary path.
- The Operations runner (`executeMobileScript`), the notebook draft and the swipe rule are covered by `src/components/operation-script.test.ts`, `src/components/operation-draft.test.ts` and `src/components/device-gesture.test.ts`. The plan builder and the Breach Room render are covered by `src/components/plan.test.ts` and `src/components/BreachRoom.test.ts`. The passkey environment and deployment constants are covered by `src/wallet/passkey-engine.test.ts`; the viewport rule by `src/platform/viewport.test.ts`.
- On mobile, the case page keeps its two primary actions — Operations and Submit — in a fixed bottom bar; desktop keeps the inline buttons and has no bar. The bar's styles live in `src/styles/passkey-mobile.css`, under the same viewport query. The level 0 tutorial is desktop-only; on mobile the start action lives inside Operations, and Submit stays disabled until an instance exists.
- `smart-account-kit` is pinned to an exact version; it is loaded lazily only when a passkey action is used.
